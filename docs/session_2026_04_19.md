# Session 2026-04-19 — Prereq Baseline for Honest-Agent Phase A

## Purpose

Before starting honest-agent Phase A, re-run the 2026-04 short-vs-long query
experiment on the post-TASK.md trie, so Phase A thresholds can be calibrated
against current behavior rather than pre-fix memory.

Experiment lives in `tests/prereq_experiment.rs`. Run with:

```
cargo test --test prereq_experiment -- --nocapture
```

## Setup

- Fresh byte-trie + fresh word-trie.
- Corpus: 5 memories (Czech spaced-repetition, Czech agent-messaging,
  Rust code snippet, Czech cooking recipe, English music theory).
- Each memory fed 3 times → ~1200 bytes written to byte-trie,
  ~50 word-tokens written to word-trie.
- ContentStore indexed by byte-trie `deepest_node` (current production
  behavior in `trie_remember`).

## Trie shape after feeding

| Trie | Total nodes | Max depth |
|------|-------------|-----------|
| Byte-trie | 3 | 2 |
| Word-trie | 2 | 1 |

**This is the central finding.** On a small mixed corpus, neither trie
builds meaningful differentiation. Byte-trie collapses to a linear
chain `root → depth-1 → depth-2`. Word-trie has two nodes total.

## Recall behavior

### Byte-trie short vs long — summary

| Query | bytes | deepest | depth | topic recalled |
|-------|-------|---------|-------|----------------|
| `"spaced repetition"` | 17 | node2 | 2 | cooking / music / spaced-rep |
| `"opakování, spaced repetition, aktivní vybavování"` | 53 | node2 | 2 | cooking / music / spaced-rep |
| `"komunikace agentů"` | 18 | node1 | 1 | code / cooking / music |
| `"komunikace mezi agenty v časově kódovaných zprávách"` | 57 | node2 | 2 | cooking / music / spaced-rep |
| `"kuře"` | 5 | node1 | 1 | code / cooking / music |
| `"pečené kuře s bramborami a rozmarýnem"` | 41 | node2 | 2 | cooking / music / spaced-rep |
| `"fn main"` | 7 | node0 | 0 | spaced-rep / agent-messaging |
| `"fn main() { let x: Vec<u8> = ... }"` | 43 | node2 | 2 | cooking / music / spaced-rep |
| `"quantum chromodynamics"` | 22 | node2 | 2 | cooking / music / spaced-rep |
| `"quantum chromodynamics gauge theory color..."` | 60 | node2 | 2 | cooking / music / spaced-rep |

**Observations:**

1. The recalled memories are **roughly independent of query content**. Any
   query of ~40+ bytes lands at `node2` and pulls the same three memories
   (cooking, music, spaced-rep) because those are the memories that happen
   to be keyed at `node2`.
2. Short queries land at shallower nodes and recall the memories keyed
   there — but the topic assignment of memories to nodes is driven by
   *when* they were written (tick order), not *what* they contain.
3. An explicitly unknown query (`"quantum chromodynamics..."`) recalls the
   exact same memories as `"opakování, spaced repetition..."`. There is
   no discrimination between known and unknown topics at this corpus
   size.

### Word-trie per-word depth — summary

Typical pattern: every word of every query lands on either `node0`
(depth 0) or `node1` (depth 1). Unknown words like `"chromodynamics"`,
`"gauge"`, `"theory"`, `"confinement"` land at `node1` — the same node
as known words like `"spaced"` and `"repetition"`. The word-trie
cannot distinguish known vocabulary from unknown vocabulary on this
corpus.

## Comparison to 2026-04 baseline

The 2026-04 observation was: *short queries fail to recall relevant
memories because byte-mass is insufficient; long queries succeed.*

**2026-04-19 finding: this is no longer the main failure mode.** The
more fundamental failure is that, on small corpora, the trie does not
build enough structure for *any* recall — long or short — to be
content-dependent. Recall becomes "whatever memory was written at the
tick range that mapped to the nearest node in a 3-node chain."

TASK.md's fix (allow depth growth) is necessary but not sufficient.
Depth only grows when incoming signals are diverse enough to exceed
a node's crystallized spectrum. English/Czech prose deltas are narrow
enough that a crystallized root absorbs most of them as `Same`.

## Implications for Phase A

1. **Recall-key strategy is too narrow.** Indexing ContentStore by
   single `deepest_node` (currently a ~3-node space) cannot support
   even minimal ANSWER/UNKNOWN discrimination. Task 01's extended schema
   already moves toward per-deposit provenance; we should also consider
   indexing by full `path_key` vector (content-addressable) rather than
   single node id.

2. **"No-hallucination on UNKNOWN" (Scenario 1) is easy to fake on this
   trie** — the baseline recall is already essentially noise, so any
   query returns irrelevant memories. "Correctly recognizing ignorance"
   requires real discrimination before it can be tested.

3. **Threshold calibration from 2026-04 is void.** The numbers in
   Task 03 (context-window enrichment) and Task 04 (confidence vector
   defaults) were chosen on the pre-fix trie with different failure
   modes. They need re-derivation after we know what a trained trie
   actually looks like.

4. **PoC Phase A must train on a larger corpus first.** Before testing
   architecture, we need a trie that has seen enough data to produce
   structured recall. 5 memories × 3 passes is an order of magnitude
   too small.

## Decision points for user

Before starting Phase A implementation (schema / context / renderer),
two scoping questions:

1. **Corpus scale.** Do we grow the prereq corpus (~200 memories across
   diverse topics, ~50k+ bytes) and re-run this baseline before Phase A
   starts? Or do we treat "small-corpus recall is noise" as Phase A's
   starting assumption and design the architecture around graceful
   degradation on undertrained tries?

2. **Index key strategy.** Stay with `deepest_node` (current behavior,
   simple but coarse) or move to `path_key` vector (content-addressable,
   more selective) as part of Task 01 schema extension?

Recommend: grow the corpus (option 1a) and switch to `path_key`
indexing (option 2b). Both are needed for Phase A tests to be
meaningful, and neither is speculative — they fall out of the
architecture as already designed.

## Addendum — Routing fix (width vs depth balance)

**Finding (pre-fix, ~9 KB diverse corpus):**
- Byte-trie: 26 nodes, max depth 25, histogram `[(0,1),(1,1),...,(25,1)]`.
- Exactly one node per depth level. Linear chain, width=1 everywhere.

**Cause:** TASK.md's Phase 2 recurses into *any* crystallized child, and
the recursive `route()` always returns `true` (Phase 3 always creates on
Different). So Phase 2 at the root always "succeeded" by growing a
grandchild, and Phase 3 at the current level never fired → no siblings.

**Fix (applied in `src/trie/write.rs::route`):** Phase 2 only recurses
into children that are ready for subtree growth — either they already
have children, or they have absorbed enough Same-hits post-crystallization
to count as mature (`visit_count >= crystallization_threshold / 4`).
Fresh childless crystallized children are skipped → Phase 3 at the
current level fires → new sibling.

**Trie shape after fix, same corpus:**
- Byte-trie: 14 nodes, max depth 6, histogram `[(0,1),(1,2),(2,2),(3,3),(4,2),(5,2),(6,2)]`.
- Word-trie: 13 nodes, max depth 5, histogram `[(0,1),(1,3),(2,3),(3,3),(4,2),(5,1)]`.
- ContentStore distinct keys: 11 (up from 3 pre-fix, and 3 post-TASK.md-only).

Real branching at every level. Multi-node widths restored; depth still
grows because diverse input (Latin + Czech + Japanese + Greek + code) has
enough delta diversity to trigger Phase 2 on heavily-visited children.

### Recall after fix — qualitative read

- `long:spaced` ("opakování, spaced repetition, aktivní vybavování")
  → correctly surfaces the `spaced-repetition` memory in top 3.
- `long:agent` ("komunikace mezi agenty...") → correctly surfaces
  `agent-messaging`.
- `long:code` ("fn main() { let x: Vec<u8>... }") → deepest node13
  at depth 6, but recalls wrong memories (config-json / gravity /
  czech-idioms). **ContentStore indexing by single `deepest_node` is
  still too coarse** — memories keyed at different nodes during write
  are not retrieved by a query landing at a deeper descendant.
- `long:unknown` ("quantum chromodynamics...") still recalls generic
  memories; the trie recognizes the input has structure but has no
  way to signal "unknown topic" at the recall layer.

### Implications for Phase A (still needed)

The routing fix is **structural**. The trie now has a usable shape.
What remains for Phase A is **layer 2**:

1. **Index ContentStore by `path_key`, not `deepest_node`.** The path
   key is content-addressable (FNV-1a over spectrum, per node, from
   leaf to root). Two queries landing at the same deepest_node but
   with different path spectrums should retrieve different memories.
2. **UNKNOWN detection needs more than "no recall."** The current
   long:unknown query lands at a deep real node and pulls whatever
   memories are keyed there. We need the mode selector (Task 05) to
   check *whether the query's path actually contains the stored
   memory's anchor*, not just "was there a hit somewhere."

Both fall naturally out of Task 01 (extended schema) + Task 04
(confidence vector). The routing fix unblocks them; it doesn't replace
them.
